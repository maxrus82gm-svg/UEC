# TRADER RULES

Правила для задач с DayZ Trader config/profile файлами.

## 1. Production path

Текущие серверные Trader-файлы лежат здесь:

- `\\192.168.0.77\Server\Dayz\Shitler_00\profiles\Trader\TraderObjects.txt`
- `\\192.168.0.77\Server\Dayz\Shitler_00\profiles\Trader\TraderConfig.txt`
- `\\192.168.0.77\Server\Dayz\Shitler_00\profiles\Trader\TraderVariables.txt`

Серверные Trader-файлы читать можно. Менять их можно только по прямой задаче пользователя. Без прямого разрешения не писать в server profile, не трогать PBO/build output и не делать build.

## 2. Связка TraderObjects и TraderConfig

`TraderObjects.txt` отвечает за физическое появление торговца или объекта на карте:

- `<TraderMarker>` — ID торговца;
- `<TraderMarkerPosition>` — координаты marker;
- `<TraderMarkerSafezone>` — радиус safezone, `0` значит без safezone;
- `<Object>` — className NPC или статического объекта;
- `<ObjectPosition>` — координаты объекта;
- `<ObjectOrientation>` — yaw, pitch, roll;
- `<ObjectAttachment>` — предметы/одежда/оружие/рюкзаки на NPC или attachment для объекта;
- `<FileEnd>` — обязателен в конце файла.

`TraderConfig.txt` отвечает за имя торговца, категории, ассортимент, цены и валюту:

- `<CurrencyName>` — текст валюты в меню;
- `<Currency>` — className валюты и номинал;
- `<Trader>` — торговец, ID задаётся порядком блоков, первый `<Trader>` имеет ID `0`;
- `<Category>` — категория внутри текущего торговца;
- item line — строка ассортимента вида `ClassName, flag, buyPrice, sellPrice`;
- `<FileEnd>` — обязателен в конце файла.

## 3. ID и безопасное добавление торговца

ID торговца в `TraderObjects.txt` должен соответствовать порядковому ID блока `<Trader>` в `TraderConfig.txt`.

Безопасный порядок добавления нового активного торговца:

1. Посчитать существующие активные `<Trader>` в `TraderConfig.txt`.
2. Добавить новый `<Trader>` в конец `TraderConfig.txt`, чтобы не сдвигать ID существующих торговцев.
3. Использовать новый ID в `<TraderMarker>` в `TraderObjects.txt`.
4. Добавить `<Object>` для NPC/объекта с координатами рядом с marker.
5. Для NPC держать `<TraderMarkerPosition>` и `<ObjectPosition>` одинаковыми или осознанно очень близкими.
6. Проверить, что `<FileEnd>` остался в конце каждого файла.

Нельзя вставлять новый `<Trader>` в середину `TraderConfig.txt` без отдельного решения: это сдвигает ID всех следующих торговцев и может привязать существующие объекты к неправильному ассортименту.

## 4. Неактивные и частично отключённые торговцы

В `TraderConfig.txt` могут быть `<Trader>` блоки без активного marker/object в `TraderObjects.txt`. Это не обязательно ошибка: такой торговец может быть подготовлен, но не заспавнен.

Если в `TraderObjects.txt` marker/object закомментирован через `//`, он не активен. При анализе считать активными только строки, которые не начинаются с `//`.

## 5. Комментарии и кодировка

Для Trader-файлов использовать только однострочные комментарии `//`.

Не использовать многострочные комментарии `/* ... */`: в шаблоне TraderConfig прямо указано, что multiline comments могут уронить сервер.

В файлах может быть кириллица и Windows-кодировка. Кривой вывод в терминале сам по себе не доказывает порчу файла. Перед правками не перекодировать весь файл и не переформатировать его целиком.

## 6. Цены и строки ассортимента

Строки ассортимента в `TraderConfig.txt` идут внутри текущей `<Category>`:

`ClassName, flag, buyPrice, sellPrice`

Практические правила:

- `ClassName` должен быть реальным className предмета.
- `flag` сохранять в стиле существующей категории (`*`, `S`, `M`, `W` и другие встречающиеся значения).
- `buyPrice = -1` обычно означает, что предмет нельзя купить у торговца.
- `sellPrice = -1` обычно означает, что предмет нельзя продать торговцу.
- Разделители и декоративные строки с `-1, -1` не добавлять без необходимости; лучше копировать стиль соседней категории.

## 7. Проверки перед отчётом

После анализа или правки Trader-файлов проверить:

- количество активных `<TraderMarker>`;
- количество активных `<Object>` для торговых NPC;
- количество `<Trader>` в `TraderConfig.txt`;
- нет ли случайного сдвига ID;
- есть ли `<FileEnd>` в конце затронутых файлов;
- не появились ли многострочные комментарии;
- не были ли изменены server profile файлы без прямого разрешения.

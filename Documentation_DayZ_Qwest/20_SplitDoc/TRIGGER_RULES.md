# TRIGGER_RULES

Правила для добавления новых quest/trigger ID и NPC-trigger в JSON квестов.

## Последовательная нумерация ID

Если у группы квестов или похожих сущностей уже есть ID с числовым суффиксом, следующий ID должен продолжать эту последовательность.

Примеры:

- есть `quest_hunter_3` -> следующий `quest_hunter_4`;
- есть `qwert_4` -> следующий `qwert_5`, потом `qwert_6`;
- есть `fishman_CHO_01` -> следующий похожий ID должен сохранять выбранный формат группы, например `fishman_CHO_02`.

Перед добавлением нового ID агент должен проверить уже существующие ID в текущем JSON и не создавать дубль.

При создании нового квеста с числовой серией агент должен сам определить следующий ID по текущему JSON:

1. найти все существующие `quests[].id` с тем же текстовым префиксом и числовым суффиксом;
2. взять максимальный номер;
3. создать следующий номер;
4. сохранить формат серии, включая ведущие нули, если они уже используются.

Примеры:

- для `quest_hunter_1`, `quest_hunter_2`, `quest_hunter_3` следующий ID — `quest_hunter_4`;
- для `fishman_CHO_01` следующий ID в той же серии — `fishman_CHO_02`;
- для `qwert_4`, `qwert_5` следующий ID — `qwert_6`.

## Добавление NPC-trigger

Новый NPC-trigger добавляется только в тот JSON, который прямо указан в задаче. Если задача не просит менять server profile, серверную копию не трогать.

При добавлении NPC-trigger:

1. проверить существующие `triggers[].id`;
2. выбрать уникальный ID;
3. сохранить старые NPC legacy-поля `npcLoadout`, `npcHandsItem`, `npcBackItems`;
4. если оружие кладется в `npcEquipment.weapons` с `target: "hands"`, не занимать `npcEquipment.hands.className`;
5. после правки проверить парсинг JSON.

## Старая корневая папка Documentation

Старая корневая папка `Documentation` удалена и больше не используется.

Полезный стартовый JSON сохранён по актуальному пути:

- `Documentation_DayZ_Qwest/21_Project_Docs/STARTER_QUEST_CONFIG.json`

Legacy bridge `Documentation/AGENT_TASK_LOOP.md` удалён. Действующая агентская система использует только активные loop и START из раздела выше.

Старые Markdown-документы сохранены в архиве:

- `Documentation_DayZ_Qwest/90_Legacy_Archive`

## Старые пути в новых задачах

Старые пути `Documentation/...` не использовать как активные источники правды.

Если старый путь встретился в текущей задаче, сначала проверить, не должен ли он быть заменён на путь внутри `Documentation_DayZ_Qwest`.

Исторические упоминания в `TASK_HISTORY`, changelog, старых отчётах и архивных заметках можно оставлять как историю.

Старую папку `Documentation` не использовать в новых задачах.

Все новые задачи, правила и проектные ссылки должны указывать на `Documentation_DayZ_Qwest`.

Если нужно посмотреть старый исторический документ, искать его в `Documentation_DayZ_Qwest/90_Legacy_Archive`.

Ссылки на `Documentation/...` допустимы только как историческое упоминание удалённого legacy bridge или другого факта прошлого этапа.

## Очистка выполненных задач

После выполнения задачи агент переносит результат в отчёт и историю, затем очищает только содержимое выполненной TASK внутри активного `БЛОКА 1` в:

- `Documentation_DayZ_Qwest/11_Задача_агенту.md`

Существующий заголовок `# БЛОК 1 — ТЕКУЩАЯ ЗАДАЧА` не удаляется, не создаётся повторно и не переносится. Структура `БЛОК 1` / разделитель / `БЛОК 2` сохраняется.

Подробный канонический алгоритм очистки находится в:

- `Documentation_DayZ_Qwest/12_Старт_агента.md`, раздел `3.2`.

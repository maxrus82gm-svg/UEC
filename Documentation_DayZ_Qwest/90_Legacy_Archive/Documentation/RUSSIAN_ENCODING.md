# Russian Text Encoding Notes

Дата: 18.04.2026

## Зачем этот файл

В проекте есть русские строки в UI, JSON, документации и комментариях. Они должны храниться в UTF-8. Если файл открыть или сохранить неправильной кодировкой, русский превращается в текст вида:

```text
Р’С‹Р±РµСЂРёС‚Рµ РєРІРµСЃС‚
РњРѕР¶РЅРѕ СЃРґР°С‚СЊ
РќР°РіСЂР°РґР°
```

Это называется mojibake.

## Почему русский ломается

Русский сам по себе не ломается. Ломается цепочка чтения/записи.

Типичный сценарий:

1. В файле лежит нормальная строка UTF-8: `Выберите квест`.
2. Инструмент читает UTF-8 байты как Windows-1251, ANSI или OEM 866.
3. На экране получается `Р’С‹Р±РµСЂРёС‚Рµ РєРІРµСЃС‚`.
4. Если этот сломанный текст сохранить обратно, файл уже реально испорчен.

Особенно осторожно с:

- Windows PowerShell 5.1;
- `cmd.exe`;
- `.bat` файлами;
- `>` и `Out-File`;
- редакторами, которые открывают файл как ANSI/Windows-1251;
- копированием текста из консоли обратно в код.

## Как отличить плохой вывод от плохого файла

Если обычный PowerShell показывает кракозябры, это еще не всегда порча файла. Консоль могла просто показать нормальный UTF-8 неправильной кодировкой.

Проверять так:

```powershell
Get-Content -Encoding UTF8 D:\Dayz\Silver_77_Quests\path\to\file.c
```

Если и при `-Encoding UTF8` внутри строк в кавычках видно `Р’С‹`, значит файл уже содержит сломанный текст.

## Правила проекта

1. Все `.c`, `.layout`, `.json`, `.md`, `.bat` хранить в UTF-8.
2. В VS Code смотреть нижний правый угол: должно быть `UTF-8`.
3. Не сохранять файлы как `Windows 1251`, `ANSI`, `OEM 866`.
4. Не переписывать русские файлы через PowerShell redirect `>` без явной кодировки.
5. Для чтения в PowerShell использовать:

```powershell
Get-Content -Encoding UTF8 path\to\file
```

6. Для bat-файлов с русским выводом держать:

```bat
chcp 65001 >nul
```

7. Перед финалом после правок искать типичные признаки mojibake:

```powershell
rg -n "Р’|Рќ|Рњ|Рџ|Рљ|РЎ|СЃ|С‚|С‹|вЂ" D:\Dayz\Silver_77_Quests
```

Важно: такой поиск может находить нормальные русские буквы тоже, поэтому он не заменяет просмотр глазами. Самые подозрительные строки обычно выглядят как `Р’С‹...`, `РњРѕ...`, `РќР°...`.

## Что делать, если текст сломался

1. Не сохранять файл повторно разными редакторами.
2. Найти нормальный источник текста:
   - монолитный корневой файл;
   - `Documentation/STARTER_QUEST_CONFIG.json`;
   - `Documentation/CODEX_WORKLOG.md`;
   - `Documentation/CODEX_CONTROL_CONTEXT.md`;
   - предыдущая рабочая копия.
3. Заменить сломанные строки вручную на нормальный русский.
4. Сохранить файл как UTF-8.
5. Проверить через `Get-Content -Encoding UTF8`.

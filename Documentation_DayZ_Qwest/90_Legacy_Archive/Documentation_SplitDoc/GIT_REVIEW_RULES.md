# GIT REVIEW RULES

Подробные правила Git / REVIEW для задач, где нужно проверять commit, push, историю репозитория, GitHub или риски Git.

## Базовое правило

Git контролирует только пользователь.

Агенту запрещено без отдельной прямой команды:

- делать `git commit`;
- делать `git push`;
- создавать или переключать ветки;
- делать `git reset`;
- делать `git clean`;
- делать `git checkout` для отката;
- откатывать чужие изменения.

Читать `git status` или историю Git можно только если это явно нужно задаче.

## Правила Git / репозитория

- Рабочий путь проекта: `P:\Silver_77_Quests`.
- Пользователь обычно сам делает commit и push.
- Codex не делает `git commit` и `git push` без прямого указания.
- После отчёта Codex ассистент проверяет GitHub.
- Ассистент сверяет последний commit с предыдущим известным состоянием.
- Если новых изменений на GitHub нет, ассистент сообщает, что push не обнаружен.
- Ассистент не утверждает, что видит локальные изменения.
- Git контролирует пользователь.
- В начале REVIEW ассистент выводит `СТАТУС КОММИТА`.

После отчёта Codex ассистент обязан попытаться получить именно commit message последнего commit на актуальной ветке.

Формат начала REVIEW:

```text
СТАТУС КОММИТА: "<commit message>"
Repository: owner/repo
Branch: main
Commit: <short sha>
Проверка: изменения найдены / push не обнаружен / требуется уточнение
```

Если commit message доступен, ассистент указывает именно его.

Если commit message короткий или неинформативный, например `+`, `01`, `02`, ассистент всё равно указывает его как есть.

Если message не подтверждён, ассистент честно пишет, что message не подтверждён, и указывает доступный ref / short SHA / результат сравнения.

## Статус чтения GitHub-репозитория

Каждый раз, когда ассистент читает данные из GitHub-репозитория, он обязан явно указать статус чтения репозитория. Это правило применяется к любому чтению GitHub-репозитория, не только к REVIEW.

Минимальный формат:

- `Repository`: owner/repo
- `Branch/ref`: main, branch, tag или explicit commit
- `Commit SHA`: short SHA или full SHA, если доступен
- `Commit message`: если доступен
- `Files read`: ключевые прочитанные файлы

Если файл читается через default branch или `main`, ассистент должен подтвердить текущий commit этой ветки и указать его в ответе.

Если пользователь дал конкретный hash, ассистент должен написать, что чтение выполнено именно по этому hash.

Если commit не удалось подтвердить, ассистент должен честно указать:

- `Commit SHA`: не подтверждён
- `Причина`: что помешало подтвердить commit

Если ассистент читает несколько файлов, он должен перечислить все ключевые прочитанные файлы.
